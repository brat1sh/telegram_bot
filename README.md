# Мониторинг отключений для 1.2 очереди (канал @cek_info)

Небольшой бот, который каждые 5 минут проверяет публичный Telegram-канал
[@cek_info](https://t.me/cek_info) и присылает в личные сообщения те посты,
где упоминается очередь **1.2**.

## Как это работает

> **Важно:** с 17 ноября 2026 проверка идёт не в GitHub, а в Cloudflare Worker —
> планировщик GitHub Actions выполнял cron «раз в 5 минут» примерно раз в час,
> из-за чего уведомления опаздывали на 30 минут. Подробности в разделе
> «Cloudflare Worker: основная проверка». Файлы `bot.py` и workflows оставлены
> как резерв и для ручного запуска.

1. Триггер по расписанию запускает проверку **каждую минуту**.
2. Скрипт скачивает **публичную веб-версию** канала — <https://t.me/s/cek_info> — обычным HTTP-запросом и разбирает HTML.
3. Из страницы извлекаются все видимые посты, у каждого берётся числовой ID из атрибута `data-post` (например `cek_info/4418` → `4418`).
4. ID последнего обработанного поста хранится в `last_seen_id.txt`.
5. Проверяются только посты с ID больше сохранённого. Пост считается важным в трёх случаях:
   * в тексте есть ключевое слово очереди (`1.2`, `1,2`, `1-2` и т. п.);
   * экстренное отключение (`екстрен`, `экстрен`, `аварійн`, `аварийн`) и упоминание города `Жовті Води` — в любом падеже и на украинском или русском;
   * экстренное отключение по всей области: либо прямо сказано про область, либо город в посте не назван вообще (канал пишет такие посты как «Шановні споживачі!»).

   Посты про экстренные отключения в **чужих** городах (Дніпро, Павлоград, Вільногірськ) игнорируются.

   При совпадении отправляется отдельное сообщение через `sendMessage`. Первая строка — короткая шапка, собранная из содержания поста, дальше полный текст и ссылка:

   ```
   Зміни в черзі 1.2 на 17 ЛИСТОПАДА

   <полный текст поста>

   https://t.me/cek_info/<ID>
   ```

   Варианты шапки:

   | Что в посте | Шапка |
   |---|---|
   | обычный график | `⚡️ Графік на 17 ЛИСТОПАДА` |
   | «повідомляємо про зміни у ГПВ» | `⚡️ Зміни в черзі 1.2 на 17 ЛИСТОПАДА` |
   | «скасовуються» | `⚡️ Скасування графіка на 17 ЛИСТОПАДА` |
   | экстренное по вашему городу | `⚡️ Екстрені відключення — Жовті Води` |
   | экстренное по области | `⚡️ Екстрені відключення — вся область` |

   Дата берётся из текста поста. Если даты в посте нет — шапка будет без неё, просто `Графік`.
6. В конце `last_seen_id.txt` обновляется до максимального найденного ID — даже если совпадений не было.

Если новых постов нет, ничего не отправляется и ничего не коммитится.

**При первом запуске** скрипт ничего не отправляет: он просто запоминает ID самого нового поста, чтобы не завалить вас старыми сообщениями.

## Что нужно сделать в Telegram

### 1. Создать бота

1. Откройте [@BotFather](https://t.me/BotFather).
2. Отправьте команду `/newbot`.
3. Придумайте имя бота (например `CEK 1.2 Monitor`) и username, заканчивающийся на `bot` (например `cek12_monitor_bot`).
4. BotFather пришлёт токен вида `1234567890:AAE...` — это и есть **BOT_TOKEN**. Никому его не показывайте.

### 2. Узнать свой Telegram ID

1. Откройте [@userinfobot](https://t.me/userinfobot) (или [@getmyid_bot](https://t.me/getmyid_bot)).
2. Отправьте `/start`.
3. Бот ответит числом, например `123456789` — это ваш **CHAT_ID**.

### 3. Обязательно написать боту /start

Бот **не может** написать первым человеку, который сам ему не писал.
Поэтому:

1. Найдите своего бота по username.
2. Нажмите **Start** (или отправьте `/start`).
3. Если этого не сделать, Telegram вернёт ошибку `403: bot can't initiate conversation with a user`, и уведомления не придут.

## Что нужно сделать в GitHub

1. Откройте репозиторий → **Settings** → **Secrets and variables** → **Actions**.
2. Нажмите **New repository secret** и добавьте два секрета:

   | Name        | Value                          |
   |-------------|--------------------------------|
   | `BOT_TOKEN` | токен от @BotFather            |
   | `CHAT_ID`   | ваш числовой Telegram ID       |

3. Проверьте, что в **Settings → Actions → General** разрешены Actions
   (для приватных репозиториев они включены по умолчанию) и что в разделе
   **Workflow permissions** выбрано **Read and write permissions** —
   иначе workflow не сможет закоммитить `last_seen_id.txt`.

Токен и chat_id нигде в коде не хранятся: `bot.py` читает их только из
переменных окружения, которые workflow берёт из secrets.

## Как дать доступ родственникам

Бот умеет отправлять сообщения сразу нескольким получателям: в секрете `CHAT_ID`
их можно перечислить через запятую. Самый удобный способ — приватный канал.

1. В Telegram: **Создать канал** → название, например «Відключення 1.2», тип — **приватный**.
2. Откройте канал → **Администраторы** → **Добавить администратора** → найдите своего бота (`@cherga_12_zv_bot`) → включите право **Публикация сообщений** → сохраните.
3. Сообщите мне, что канал готов, — я найду его ID сам (он виден боту после добавления).
4. В GitHub → Settings → Secrets and variables → Actions обновите `CHAT_ID`, перечислив получателей через запятую:

   ```
   127592322,-1001234567890
   ```

   Первый адрес — ваш личный, второй — канал. Личные сообщения при этом останутся.
5. Родственникам отправьте ссылку-приглашение: канал → **Пригласить по ссылке**.

Важно: канал должен быть **приватным**, иначе посты увидит любой, кто его найдёт.
Бот обязан быть администратором — без этого права Telegram не даст ему публиковать.

Если в `CHAT_ID` указать несколько адресов, а один из них окажется неверным,
сообщение всё равно уйдёт остальным, а в логе появится, какому получателю
(по порядку) доставить не удалось.

## Как запустить вручную

1. Вкладка **Actions**.
2. Слева выберите workflow **Check CEK outages**.
3. Кнопка **Run workflow** → ветка `main` → **Run workflow**.
4. Откройте появившийся запуск и смотрите лог шага **Check posts for outages**.

При первом ручном запуске в логе будет «Первый запуск: запоминаю самый новый пост …», и сообщение не придёт — это нормально. Чтобы проверить доставку, дождитесь нового поста с упоминанием вашей очереди или временно удалите `last_seen_id.txt` из репозитория (тогда бот снова запомнит только последний пост, но уже не отправит старые).

## Про расписание

* GitHub Actions **не гарантирует** запуск ровно каждые 5 минут: задержка в 5–20 минут — обычное дело, а в часы пик бывает и больше.
* Если репозиторий долго не имеет активности, GitHub может временно отключать scheduled workflows — тогда достаточно зайти в **Actions** и нажать **Enable workflow**.
* Cron в GitHub работает в UTC и не учитывает переход на летнее время, но для интервала «каждые 5 минут» это не важно.

## Как поменять очередь, город или ключевые слова

Всё настраивается константами в начале `bot.py`.

**Очередь** — список `KEYWORDS`. Например, для очереди 2.1:

```python
KEYWORDS = (
    "2.1 черга",
    "2,1 черга",
    "2.1",
    "2,1",
    "2-1",
    "2–1",
)
```

Сравнение идёт **без учёта регистра** и как простая подстрока, поэтому
короткие значения вроде `1.2` могут иногда совпадать с посторонними числами
(`1.25`, `1.2 кВт`). Если ложных срабатываний станет много, оставьте только
длинные варианты с словом «черга».

**Город для экстренных отключений** — две константы:

```python
CITY_NAME = "Жовті Води"
CITY_PATTERNS = (
    r"жовт\w*\s+вод\w*",
    r"желт\w*\s+вод\w*",
)
```

`CITY_NAME` подставляется в заголовок сообщения. `CITY_PATTERNS` — регулярные
выражения, которые ищут город в любом падеже: «ЖОВТІ ВОДИ», «у Жовтих Водах»,
«мешканцям Жовтих Вод», «Желтые Воды». Если переедете или смените город,
поправьте оба значения — например для Павлограда это будет
`CITY_NAME = "Павлоград"` и шаблон `r"павлоград\w*"`.

Слова, по которым распознаётся экстренное отключение, лежат в
`EMERGENCY_KEYWORDS` (`екстрен`, `экстрен`, `аварійн`, `аварийн`).

Правила для экстренных постов, по порядку:

1. назван ваш город → уведомление с заголовком «… — Жовті Води»;
2. названа область (`REGION_PATTERNS`: «всій області», «по всій області», «Дніпропетровській області») → уведомление с заголовком «… — вся область»;
3. город не назван вообще → тоже считаем общим, заголовок «… — вся область»;
4. назван чужой город (Дніпро, Павлоград, Вільногірськ) → пропускаем.

Текст шапок задаётся константами в `bot.py`:

```python
QUEUE_NAME = "1.2"
HEADER_ICON = "⚡️"
HEADER_SCHEDULE = "Графік"
HEADER_CHANGES = f"Зміни в черзі {QUEUE_NAME}"
HEADER_SCHEDULE_CANCELLED = "Скасування графіка"
HEADER_EMERGENCY = "Екстрені відключення"
HEADER_EMERGENCY_CANCELLED = "Скасування екстрених відключень"
```

`HEADER_ICON` подставляется в начало каждой шапки. Если молния надоест,
достаточно поставить `HEADER_ICON = ""`.

Тип объявления определяется по первым 250 символам поста (`HEADLINE_CHARS`) —
именно там написана суть, дальше идёт сам график. Если хотите шапку на русском,
просто замените строки, например `HEADER_SCHEDULE = "График"`.

## Cloudflare Worker: основная проверка

Проверку выполняет Worker `cek-monitor` в аккаунте Cloudflare:

- **расписание:** `* * * * *` (каждую минуту, UTC);
- **код:** `cloudflare/worker.mjs` в этом репозитории;
- **состояние:** KV namespace `cek-monitor-state`, ключ `last_seen`;
- **настройки (bindings):** `BOT_TOKEN` (секрет), `CHAT_ID` (ID канала), `STATE` (KV);
- **алгоритм:** тот же, что в `bot.py` — те же ключевые слова, город, правила экстренных постов и шапки сообщений.

Почему так: GitHub Actions выполнял cron «каждые 5 минут» примерно **раз в час** (планировщик GitHub работает по возможности, а не по секундомеру). Из-за этого уведомление о вечернем графике пришло с задержкой 32 минуты. Cloudflare запускает проверку каждую минуту, фактическая задержка — около минуты.

**Где смотреть:** <https://dash.cloudflare.com> → Workers & Pages → `cek-monitor`. Там же логи и KV-хранилище.

**Лимиты бесплатного плана:** 10 мс CPU на запуск, до 3 cron-триггеров, 100 000 запросов в сутки. Наша проверка укладывается с запасом.

**GitHub теперь — резерв.** Все три workflow переведены в `disabled_manually`. Ручной запуск по-прежнему возможен (Actions → Run workflow), но у него отдельное состояние в `last_seen_id.txt`, поэтому при ручном запуске возможен дубль уже отправленного поста.

## Важные ограничения

* Бот **не читает канал через Bot API** и не является его администратором — он работает только с публичной веб-версией `https://t.me/s/cek_info`.
* Если Telegram изменит вёрстку веб-версии, скрипт сообщит об этом в логе («на странице не найдено ни одного поста») и не станет отправлять мусор.
* Если отправка сообщения не удалась (сеть, лимиты Telegram), `last_seen_id.txt` не продвигается за этот пост, и попытка повторится при следующем запуске — уведомление не потеряется.
* Бот не заменяет официальный график: сообщения носят информационный характер.

## Локальный запуск (по желанию)

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate

pip install -r requirements.txt

# Windows PowerShell
$env:BOT_TOKEN="ваш_токен"; $env:CHAT_ID="ваш_id"; python bot.py
```

Не создавайте файл `.env` с токеном в репозитории — он в `.gitignore`,
но безопаснее вообще не хранить токен на диске.

## Файлы проекта

| Файл | Назначение |
|------|------------|
| `bot.py` | основная логика (резервная версия для GitHub Actions) |
| `cloudflare/worker.mjs` | рабочая версия: проверка в Cloudflare Worker каждую минуту |
| `requirements.txt` | зависимости (`requests`, `beautifulsoup4`) |
| `.github/workflows/monitor.yml` | запуск по расписанию и коммит состояния |
| `last_seen_id.txt` | ID последнего обработанного поста (создаётся автоматически) |
